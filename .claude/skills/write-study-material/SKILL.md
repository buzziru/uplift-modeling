# 학습 자료 쓰기

학습 자료는 사용자가 단계(U1, M3 등)를 시작하기 전이나 끝낸 뒤에 그 단계의 이론과 이 프로젝트에서 실제로 한 일을 익히려고 읽는 문서다. 사용자는 자료를 다른 AI에게 붙여 넣고 질문하기도 한다. 폴더는 `_workspace/study/`이고 git이 추적하지 않는다.

문체와 개념 설명 순서는 `~/.claude/rules/`의 `writing-style.md`, `korean-writing.md`, `explanation.md`를 따른다. 이 스킬은 그 규칙에 없는 것만 정한다.

## 1. 독자 수준

독자는 데이터 과학자다. 독자에게 모자라는 것은 용어 정의가 아니라 기제(왜 그렇게 되는가)와 구성 요소의 구체적인 모양(무엇을 입력받아 무엇을 내고, 어느 행으로 학습하고, 그 출력의 어느 값을 다음 계산에 쓰는가)이다. 이 둘을 빠뜨리면 사용자가 다시 묻는다.

## 2. 파일 구성

1. 제목: `# <단위> 학습 자료: <주제>`. 파일 이름은 `<단위>-<주제>-easy.md`이고, 다른 자료가 가리키는 이름은 바꾸지 않는다.
2. 머리 두세 문장: 이 단위가 무엇을 정하는 단계인지, 이 자료가 다루는 것과 다루지 않는 것.
3. 수치 표시 줄: "결과 파일 경로를 붙인 수치는 실제 분석 결과, '계산'은 이 글에서 스크립트로 계산한 값, '설명용 가상 예'는 지어낸 작은 예"를 적는다.
4. 0절 맥락: 데이터, 목표, 단계 순서, 이미 정한 것(결정과 그 정본 위치), 아직 정하지 않은 것과 정할 때. 파일 하나만 다른 AI에게 붙여도 질문할 수 있어야 한다.
5. 본문. 이론 다음에 "이 프로젝트에서는" 절을 두어 실제 구현(코드 위치, 라이브러리가 실제로 하는 일)과 결과 수치를 붙인다. 단계가 아직 진행되지 않았으면 지금 계획이라고 밝히고 결과 절을 두지 않는다. 계획 단계 자료는 기제를 설명하다 구현 방식(추정량, 깊이, 시험 세트 사용, 화면 문구)까지 서술형으로 단정하기 쉽다. 그런 문장마다 "정한 것(결정 날짜)", "지금 계획", "내 판단", "정하지 않았다" 가운데 하나를 붙인다. 정한 것이라고 쓰기 전에 그 결정이 어느 결과 변수와 범위에 걸린 것인지 확인한다(예: Hájek 결정은 `visit`에만 걸렸다).
6. 참고문헌.

결정은 "사용자 결정 2026-11-26"처럼 날짜와 결정 주체로 적고, 반영된 정본(코드, 설정, 실험 기록)이 있으면 그 위치를 붙인다. 기록 문서와 단계 계획을 가리킬 수 있는지는 `.claude/rules/docs.md`를 따른다. 학습 자료도 `docs/` 밖 파일이다.

자료 하나에 담기 어려우면 파일을 나눈다(예: 방법 정의와 비교 설계·결과). 본문을 이해하는 데 필요한 정의, 유도, 숫자 예는 그 파일 안에 둔다. 다른 파일이나 `docs/`는 더 읽을 거리로만 가리킨다.

## 3. 설명 방법

1. 독자가 이미 아는 전제는 짧게 확인하고, 절은 남는 질문 하나로 연다. 절 제목에는 그 질문의 답(결론)을 쓴다.
2. 기제는 변수 하나만 바꾼 숫자 대조로 보인다. 예: 방문율을 20%로 묶고 일치 고객 수만 20,000명과 22,000명으로 바꾸면 IPW만 0.200에서 0.220으로 바뀐다.
3. 고객 한 명 단위의 계산을 끝까지 보인다. 중간값이 확률이나 결과가 아니면 그렇다고 적는다(예: AIPW 몫 1.6은 방문 확률이 아니다).
4. 모델과 구성 요소는 입력과 출력의 모양을 적는다. 학습에 쓰는 행, 출력 배열의 모양(고객 수 × 메일 수), 정책이나 지표가 그 출력의 어느 값을 쓰는지까지 적는다.
5. 이름이 비슷하거나 같은 데이터를 쓰는 구성 요소는 역할 차이를 따로 적는다(예: 반응 모델과 uplift 모델, U3의 OOF와 AIPW의 OOF).
6. 방법 사이의 관계는 "앞 방법에서 무엇 하나를 바꿨나"로 적는다(예: Hájek은 IPW에서 분모만 바꾼다).
7. 결론은 일반적으로 맞는 말과 이 데이터에서 맞는 말로 나눠 쓴다.
8. 라이브러리가 하는 일은 문서나 기억이 아니라 설치된 소스로 확인한다. 이름이 같아도 구현이 교과서 정의와 다를 수 있다.

## 4. 수치

- 설명용 가상 예를 포함한 모든 계산 값은 scratchpad의 스크립트로 계산해 옮긴다. 손으로 계산한 값을 그대로 쓰지 않는다.
- 결과 파일 수치는 `artifacts/<ID>/tables/` 파일을 열어 옮기고 경로를 붙인다. summary.md의 수치를 다시 옮길 때도 표 파일과 대조한다.
- 같은 예를 여러 절에서 쓰면 수치를 한 번 정하고 끝까지 같은 값을 쓴다.
- 표의 데이터 범위(전체 64,000명, 학습 세트, 시험 세트)가 문장의 범위와 같은지 본다. `artifacts/ANA-001/tables/ate.csv`처럼 전체 데이터 표를 학습 세트 수치의 근거로 붙이지 않는다.
- 단계 계획이나 summary.md에서 가져온 수치는 원 표 파일을 찾아 그 경로를 붙인다. "(ANA-002)"처럼 분석 ID만 적지 않는다.

## 5. 원천을 읽는 순서

1. 정본: 코드(`src/uplift/`), 설정(`experiments/<ID>/config.yaml`), 테스트.
2. 실험 기록(`experiments/<ID>/experiment.md`)과 결과(`artifacts/<ID>/summary.md`, `tables/`).
3. 기록 문서(`docs/`)의 결정 항목, 단계 계획(`docs/plans/`), `_workspace/PROGRESS.md`의 진행 중인 일.
4. 이론 배경(`docs/THEORY.md`)과 참고문헌.

옛 학습 자료는 원천이 아니다. 단계가 진행되며 틀린 내용이 생기므로 다시 쓸 때는 정본과 결과로 확인한다. 덮어쓰기 전에 옛 파일을 `_workspace/archive/`에 복사한다.

## 6. 쓰지 않는 것

- 승인 지점(`.claude/rules/approvals.md`)의 결정을 자료 안에서 정하지 않는다. 선택지와 근거를 보이고 "정하지 않았다"고 적는다. 내 판단은 "내 판단"이라고 밝힌다.
- 수사 질문("왜 그럴까요?", "결과는 어디서 갈리는가.")과 목록 앞의 개수 예고("결론은 두 가지다", "읽을 것은 둘이다")를 쓰지 않는다. 목록을 바로 쓴다.
- 해석과 인과 서술("차이가 작은 이유는 ~", "~라 이득이 작을 수 있다")은 결과 표가 직접 보이지 않으면 "내 판단"으로 표시하고, 확인하지 못한 고리를 적는다.

## 7. 다 쓴 뒤 점검

1. 0절만 읽고도 데이터, 목표, 이 단위의 위치를 알 수 있는가.
2. 본문에 나온 모델마다(비교 대상인 반응 모델 등 포함) 입력, 학습 행, 출력 모양이 적혀 있는가. 앞 단위 개념(IPW, Hájek, AIPW 등)을 쓰면 그 파일 안에 한두 문장 정의가 있는가.
3. 수식 전개마다 각 단계의 근거가 있는가. "유도는 N절"처럼 약속한 전개가 그 절에 실제로 있는가. 기호를 정의 전에 쓰거나 절 사이에서 기호를 바꾸지 않았는가(바꾸면 바꾼다고 적는다).
4. 절 제목이 결론 문장인가("한눈에 보기", "말하는 범위" 같은 이름표가 아닌가).
5. 계산 값은 스크립트로 확인했고, 실제 결과 수치에는 경로가 있는가.
6. 결정된 것, 지금 계획, 정하지 않은 것이 섞이지 않았는가.
7. 라이브러리 동작 서술을 소스와 대조했는가.
8. 위 문체 규칙과 6절이 금지한 꼴이 없는가.

자료를 여러 개 쓰면 첫 자료를 쓴 뒤 작성 맥락이 없는 서브에이전트에게 이 점검 목록과 원천 파일로 검토를 맡기고, 되풀이되는 지적은 이 스킬에 반영한 뒤 나머지를 쓴다.

## 8. 되풀이된 문제

작성하며 같은 문제가 두 번 나오면 여기에 한 줄로 더하고, 위 절의 규칙으로 옮길 수 있으면 옮긴다.

- 2026-11-27 U4\~M4 작성: 기록 문서 항목 인용(2절로 옮김), 전체 데이터 표를 학습 세트 근거로 씀·계획에서 옮긴 수치에 원 표 경로 없음(4절로 옮김), 예고 문장과 개수 예고·판단 표시 없는 해석(6절로 옮김), 약속한 전개 빠짐·기호 전환·이름표 절 제목·비교 대상 모델의 입출력 누락(7절로 옮김). 라이브러리 구현이 옛 자료와 달랐다(causalml S-learner는 메일마다 모델을 따로 만든다): 3절 8항으로 막는다.
- 2026-11-27 둘째 검토: 계획 단계 자료(U6, U7, M3, M4)에서 열린 결정을 단정한 곳이 아홉 군데, 결정의 적용 범위를 넓혀 쓴 곳(`visit`의 Hájek 결정을 `spend`에 씀)이 두 군데였다. 2절 5항으로 옮겼다. 반올림한 값으로 다시 계산해 표와 다른 값을 "계산으로 확인"이라 적은 곳이 있었다: 계산은 표와 같은 정밀도로 하고, 다르면 차이를 적는다.
