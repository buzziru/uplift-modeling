# 문서 체계

| 층 | 파일 | 담는 것 |
| --- | --- | --- |
| 정본(결정) | 코드, 설정, 테스트 | 결정 |
| 정본(작업 규약) | 폴더의 `CLAUDE.md`, `.claude/rules/`, 스킬, `experiments/TEMPLATE.md` | 작업 규약과 실험 양식 |
| 시작 명세 | `SPEC.md`(고정) | 프로젝트를 시작할 때 정한 요구 사항과 계획. 고치지 않고, 처음 계획과 실제 진행을 비교하는 자료로 쓴다 |
| 단계 계획 | `docs/plans/`(`ROADMAP.md`와 마일스톤별 계획) | 지금의 마일스톤, 단계별 범위, 완료 기준, 미결 사항, 작업 분해, 단위별 메모, 아이디어. 기록 문서에 둘 결정은 다시 적지 않는다 |
| 기록 문서 | `docs/`의 PROBLEM, DATA, MODELING, EVALUATION, POLICY, DASHBOARD, ENGINEERING, NARRATIVE | 결정 당시의 결정, 근거, 기각한 대안, 반영 위치 |
| 이론 | `docs/THEORY.md` | 이론 배경 |
| 용어집 | `docs/glossary.md` | 용어집 기준에 드는 말의 뜻과 처음 쓴 곳 |

- 사실은 한 층에만 둔다.
- `docs/` 밖의 파일은 기록 문서의 절을 인용하지 않고, 어느 파일도 시작 명세(`SPEC.md`)에 맞추거나 인용하지 않는다. `.claude/harness/check_docs.py`가 기록 문서 인용을 막는다.
- 다른 파일은 단계 계획의 내용을 인용하지 않는다. 폴더 규약이 지금 계획의 자리로 `docs/plans/` 폴더를 가리키는 것은 인용이 아니다. 계획에서 나온 것이 결정이 되면 정본과 기록 문서에 남긴다.
- `docs/THEORY.md`와 `docs/glossary.md`는 다른 파일이 가리킬 수 있다.
- 용어집에는 일반 뜻이나 분야에서 정착한 뜻으로 읽으면 잘못 읽히는 말과 프로젝트에서 새로 만든 말만 올린다. 일반 뜻과 문맥으로 읽히는 말, 정착한 분야 용어, 다른 정본이 정의한 말은 올리지 않는다. 올릴 말은 문서에 처음 쓸 때 한국어 이름, 정의, 처음 쓴 곳을 함께 적고, 올리기 전에 정착한 용어가 있는지 찾는다.
