# 분석 산출물 루브릭

> 항목 번호는 한 번 쓰면 바꾸지 않는다. 대기 목록이 `<이 파일>#R<번호>`로 같은 항목을 센다. `new`는 번호로 쓰지 않는다(solo-harness `docs/formats.md` 6-2절).

첫 항목은 SPEC.md 13절과 15절의 품질 목표에서 옮긴다. 항목은 같은 지적이 두 작업에서 나올 때 더한다. 항목마다 평가 에이전트가 읽을 판정 근거 위치를 `근거:` 줄에 적는다. 아직 없는 경로에 기대는 조건은 그 경로를 만드는 작업에서 더한다.

## R1. 수치는 결과 파일에서 온다

분야 문서와 NARRATIVE.md의 수치마다 그것을 만든 결과 파일 경로와 조건(데이터 범위, 행 수, 기준선)이 붙어 있으면 통과다. 출처 없는 수치나 결과 파일과 다른 수치는 지적이다.

근거: `docs/` 아래 문서의 수치와 그 수치가 가리키는 결과 파일.

## R2. 시험 세트를 모델 선택에 쓰지 않는다

모델과 하이퍼파라미터를 고르는 코드가 시험 분할을 읽지 않으면 통과다. 읽으면 must다. `src/`가 생기기 전에는 해당 없음으로 판정한다. 시험 세트를 한 번만 쓰는지 보는 조건은 시험 평가 스크립트를 만드는 작업에서 더한다.

근거: `src/`와 실행 스크립트의 모델 선택 코드.

## R3. 결정에는 근거와 기각한 대안이 있다

분야 문서의 결정 절마다 결정 하나와 그 근거, 기각한 대안이 있으면 통과다. 사용자 지시로 정한 결정도 실제로 있던 대안과 기각 이유를 적는다. 기각한 대안이 "없음"이거나, 한 절에 서로 다른 결정이 여럿 있으면 지적이다. SPEC.md 11절의 승인 지점에 드는 결정이 결정 절에 `승인: <날짜>` 줄 없이 확정으로 적혀 있으면 지적이다.

근거: `docs/` 아래 분야 문서의 결정 절.

## R4. 비즈니스 판단으로 이어진다

결과가 "누구에게 어떤 메일을 보내야 이익이 큰가"에 답하는 문장(정책, 세그먼트, 증분 이익)으로 정리되고, 전체 발송과 반응 모델 정책 대비 증분 이익이 비교돼 있으면 통과다. 기준선보다 낫지 않으면 그 이유가 수치로 설명돼 있어야 한다. 비용과 가치 가정에 출처가 없거나, 모델 지표만 있고 정책 수준 해석이 없으면 지적이다.

근거: `docs/POLICY.md`, `docs/EVALUATION.md`, `docs/NARRATIVE.md`.

## R5. 다시 실행하면 같은 결과가 나온다

분석과 학습이 `src/` 모듈과 실행 스크립트로 돌고 시드가 설정에 고정돼 있으면 통과다. 노트북에만 있는 계산이나 고정되지 않은 난수는 지적이다. `src/`가 생기기 전에는 해당 없음으로 판정한다. 허용 오차 안의 재현 여부는 회귀 테스트가 맡고, 이 항목에서 보지 않는다.

근거: `src/`, 실행 스크립트, 설정 파일.

## R6. 새 내부 용어가 용어집에 있다

분야 문서와 NARRATIVE.md에서 프로젝트가 특정한 뜻으로 쓰는 용어가 한국어 이름, 정의, 처음 쓴 곳과 함께 용어집에 있으면 통과다. 빠졌으면 지적이다.

근거: `docs/glossary.md`와 평가 입력 문서.

## R7. 마일스톤의 성과 자료가 NARRATIVE.md에 있다

마일스톤을 닫는 작업이면 그 단계의 주장 문장, 근거 수치(조건과 결과 파일 경로), 그림 값이 있으면 통과다. 그림 값은 사이트가 그릴 수치(기준선과 최종값, 차이의 95% 구간, 세그먼트별 효과 등)와 그 수치를 만든 결과 파일 경로다. 빠졌으면 지적이다.

근거: `docs/NARRATIVE.md`.

## R8. 같은 대상을 정하는 문서끼리 어긋나지 않는다

평가 입력 문서가 같은 대상을 정하는 다른 문서(SPEC.md, 분야 문서, 용어집)와 맞고, 정의나 결정 값을 다시 적지 않고 가리키며, 가리키는 절 이름과 파일이 실제로 있으면 통과다. 두 문서가 같은 대상을 다르게 정하거나, 정의를 다른 말로 다시 적었거나, 없는 절을 가리키면 지적이다.

근거: 평가 입력 문서, SPEC.md 10절 표에서 같은 대상을 맡은 분야 문서, `docs/glossary.md`.
