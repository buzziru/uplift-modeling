# 분석 산출물 루브릭

> 항목 번호는 한 번 쓰면 바꾸지 않는다. 대기 목록이 `<이 파일>#R<번호>`로 같은 항목을 센다. `new`는 번호로 쓰지 않는다(solo-harness `docs/formats.md` 6-2절).

첫 항목은 프로젝트 명세(SPEC.md 13절, 15절)의 품질 목표에서 옮긴다. 항목은 같은 지적이 두 작업에서 나올 때 더한다.

## R1. 수치는 결과 파일에서 온다

분야 문서와 NARRATIVE.md의 수치마다 그것을 만든 결과 파일 경로와 조건(데이터 범위, 행 수, 기준선)이 붙어 있으면 통과다. 출처 없는 수치나 결과 파일과 다른 수치는 지적이다.

## R2. 시험 세트를 모델 선택에 쓰지 않는다

모델과 하이퍼파라미터 선택이 학습 세트 CV로만 이뤄지면 통과다. 시험 세트 결과를 보고 선택을 바꾼 흔적이나 시험 세트를 두 번 이상 쓴 흔적은 must다.

## R3. 결정에는 근거와 기각한 대안이 있다

분야 문서의 결정 절마다 결정, 근거, 기각한 대안이 있으면 통과다. 승인 지점의 결정이 사용자 승인 기록(커밋 메시지나 대화) 없이 확정으로 적혀 있으면 지적이다.

## R4. 비즈니스 판단으로 이어진다

결과가 "누구에게 어떤 메일을 보내야 이익이 큰가"에 답하는 문장(정책, 세그먼트, 증분 이익)으로 정리돼 있으면 통과다. 비용과 가치 가정에 출처가 없거나, 모델 지표만 있고 정책 수준 해석이 없으면 지적이다.

## R5. 다시 실행하면 같은 결과가 나온다

분석과 학습이 `src/` 모듈과 실행 스크립트로 돌고 시드가 설정에 고정돼 있으면 통과다. 노트북에만 있는 계산이나 고정되지 않은 난수는 지적이다.
