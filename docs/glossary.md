# 용어집

프로젝트 안에서 특정한 뜻으로 쓰는 용어를 모은다. 새 용어는 문서에 처음 쓸 때 여기에 함께 적는다.

| 용어 | 정의 | 처음 쓴 곳 |
| --- | --- | --- |
| 정책 가치 | 정해진 타겟팅 정책대로 메일을 보냈다면 얻었을 평균 결과(방문, 매출, 이익). | SPEC.md |
| 증분 이익 | 정책을 따랐을 때의 이익에서 아무에게도 보내지 않았을 때의 이익을 뺀 값. 증분 매출 × 마진 − 발송 비용으로 계산한다. | SPEC.md |
| 반응 모델 | 처치 효과가 아니라 메일을 받았을 때의 반응 확률로 대상을 고르는 모델. 비교 정책의 하나다. | SPEC.md |
| 세그먼트 규칙 | 추정한 처치 효과를 얕은 의사결정나무(surrogate tree)로 근사해 얻은, 사람이 읽을 수 있는 고객군 정의. | SPEC.md |
| Sleeping Dogs | 메일을 받으면 반응이 오히려 줄어드는, 처치 효과가 음수인 고객군. | SPEC.md |
| 기준값 파일 | 채택한 실행의 지표를 고정한 파일. 회귀 테스트가 새 결과를 이 값과 비교한다. | SPEC.md |
| 승인 지점 | 작업을 멈추고 사용자 승인을 받는 결정. | SPEC.md 승인 지점 절 |
| base learner | uplift 방법 안에서 반응 함수나 처치 효과를 학습하는 일반 회귀·분류 모델. 한국어 글에서는 기본 학습기라고도 한다. uplift random forest처럼 자체 트리를 쓰는 방법에는 없다. | SPEC.md |
| 실행 | 실험 하나를 한 설정으로 한 번 돌린 것. DuckDB에서 `run_id`로 구분한다. | `docs/DATA.md` |
| OOF 예측 | 학습 세트 안 CV에서 각 고객을 그 고객이 빠진 fold로 학습한 모델로 예측한 값. | `docs/MODELING.md` |
| 실험(EXP) | `experiments/EXP-<번호>-<주제>/`에 설정과 실행 스크립트를 두고 다시 돌려 비교하는 모델 작업. | `docs/ENGINEERING.md` |
| 분석(ANA) | `analyses/ANA-<번호>-<주제>.py` marimo 노트북에서 한 번 보고 판단하는 작업. | `docs/ENGINEERING.md` |
| 산출물 폴더 | 실험과 분석의 결과 파일을 ID별로 두는 `artifacts/<ID>/`와 데이터 적재 산출물을 두는 `artifacts/data/`. | `docs/ENGINEERING.md` |
| 설계 절 | `experiment.md`에서 질문을 무엇으로 재고 결과를 어떻게 판단할지 결과를 보기 전에 적어 커밋하는 절. | `experiments/TEMPLATE.md` |
| 판정 규칙 | 결과를 보기 전에 정하는, 어떤 결과면 무엇을 할지의 규칙. | `experiments/TEMPLATE.md` |
| 이미 본 것 | 판정 규칙을 정하기 전에 본 데이터와 결과. 결과를 본 뒤 정한 규칙을 미리 정한 규칙과 구분하게 한다. | `experiments/TEMPLATE.md` |
| 퍼널 단계 | 고객의 결과를 방문 안 함, 방문만, 구매의 세 단계로 나눈 값. 구매하면 늘 방문했으므로 `visit`과 `conversion`을 한 변수로 센다. | `docs/DATA.md` |
| 고른 정책 | 모델 선택으로 고른 모델이 고객마다 보낼 메일을 정하는 정책. | SPEC.md 완료 기준 절 |
| 통계적 성공 | 완료 기준 2번의 판정. | `docs/PROBLEM.md` |
| 비즈니스 판단 | 정책이 이익을 내는지를 금액으로 보이는 보고. | `docs/PROBLEM.md` |
| 퍼널 분해 | 고객별 증분 금액을 `visit` uplift, 처치별로 늘어난 방문 1회당 구매, 구매 시 금액의 곱으로 만드는 금액 모델. | `docs/MODELING.md` |
| 기록 문서 | 결정 당시의 결정, 근거, 기각한 대안, 반영 위치를 남기는 `docs/` 문서(`docs/THEORY.md`, `docs/glossary.md` 제외). | SPEC.md 문서 체계 절 |
| 판정 기준의 비용 | 판정 규칙 때문에 잃는 것. 구간으로 판정하면 구간 반폭보다 작은 실제 개선을 "크다"로 판정하지 못한다. 그 크기는 검정력 80%에서의 최소 효과(MDE)로 잰다. | `docs/PROBLEM.md` |
| 전체 발송 정책 | 모든 고객에게 한 종류의 메일을 보내는 비교 정책. | `docs/PROBLEM.md` |
| 무작위 타겟팅 | 모델 없이 무작위로 대상이나 처치를 고르는 비교 정책. | `docs/PROBLEM.md` |
| 구매 상품 세그먼트 | `mens`, `womens`로 고객을 남성 상품만, 여성 상품만, 둘 다 산 고객으로 나눈 값. 둘 다 사지 않은 고객은 없다. | `docs/DATA.md` |
| 단계 계획 | 마일스톤마다 작업 분해와 단위별 메모, 앞 단계 분석의 아이디어를 모은 `docs/plans/` 문서. 기록 문서나 정본이 아니다. | `docs/CLAUDE.md` |
| 비교 정책 | uplift 모델로 만든 정책과 정책 가치, 순위 품질을 비교하는 정책. ML에서 새 모델이 넘어야 할 단순한 모델(베이스라인 모델)과 다르다. | SPEC.md |
