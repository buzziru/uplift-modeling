# docs 규약

## 기록 문서

- 머리말에 "결정 당시 기록이며 지금 규칙과 다를 수 있다"를 둔다. 포트폴리오와 면접의 재료로 쓴다.
- 항목은 "결정 / 근거(수치와 결과 파일 경로) / 기각한 대안 / 정본(반영된 위치)"을 두고, 제목 앞에 결정한 날짜를 쓴다. NARRATIVE.md는 마일스톤별 성과 자료이고 형식은 아래 NARRATIVE.md 절이다.
- 정본 칸이 반영 전이면 "- 정본: 아직 없음. <반영할 곳>." 꼴로 쓴다. 일부만 반영했어도 이 꼴로 쓴다.
- 뒤 결정이 앞 결정을 바꾸면 새 항목을 더하고, 근거에 바꾸는 앞 항목 제목을 적는다. 앞 항목은 결정 문장을 그대로 두고 끝에 "- 바뀐 이력: <날짜>, <새 항목 제목>으로 바뀜" 한 줄만 더한다. 제자리 수정은 결정이 바뀌지 않는 정정(오타, 수치 오류)에만 쓴다.
- 바뀐 이력 줄이 문서 전체 줄의 20%를 넘으면, 그 문서의 바뀐 이력을 `docs/history/<문서 이름>.md`로 옮기고 각 항목에는 옮긴 곳을 한 줄로 남긴다. `.claude/harness/check_docs.py`가 비율을 재어 넘으면 알린다.

## 단계 계획

- `docs/plans/ROADMAP.md`는 프로젝트 전체의 지금 계획(마일스톤, 단계별 범위, 완료 기준, 미결 사항)이고, 계획이 바뀌면 고친다. 마일스톤별 계획은 `docs/plans/M<번호>-PLAN.md`로 둔다.
- 단계의 구현 계획을 세울 때 `uv run python .claude/harness/check_docs.py --pending`으로 그 단계에서 반영할 기록 항목을 모은다. 같은 곳에 반영할 항목끼리 충돌하면 각 결정이 쓰인 맥락, 선택지의 장단, 효과와 비용을 검토해 정한다. 사용자 승인 지점이면 묻는다.

## NARRATIVE.md

각 마일스톤을 마칠 때 그 단계의 성과 자료를 더한다. 자료는 세 가지다.

- 주장 문장: 무엇을 판단했고 결과가 어땠는지를 한 문장으로 쓴다.
- 근거 수치: 조건(데이터 범위, 행 수, 기준선)과 결과 파일 경로를 함께 적는다.
- 그림 값: 기준선과 최종값, 차이의 95% 구간, 세그먼트별 효과처럼 사이트가 그릴 값을 적는다.

사이트 항목의 형식(필드, 그림 데이터 형식)은 사이트 저장소의 콘텐츠 스키마를 따른다.
